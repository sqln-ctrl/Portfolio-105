4. Services section logic
The supplied reference contains six services: AI Agents, Automations, Web Development, App Development, Ecommerce Solutions and Content Management. Keep these names as the service taxonomy unless the founders later decide otherwise. Each card should answer three things: what we make, who it helps, and what outcome it creates.

5. Work archive
Do not build a generic 3x3 portfolio grid as the final concept.
Use a controlled editorial field: a few large projects, mixed scale, intentional whitespace.
A project card should reveal role, category, short result and year on interaction.
Project detail should feel like a case study, not a gallery.
6. Case study template
1. Hero + one-line outcome.
2. Context / problem.
3. Approach / strategy.
4. Design evolution.
5. Build / technology.
6. Interaction or technical showcase.
7. Outcome / result.
8. What we learned.
9. Next project link.
7. Conversion logic
Every major section should naturally point to the next question. Hero → work. Work → capabilities. Capabilities → process. Process → about/trust. About → contact. Avoid repeated “Book a call” buttons every 100px.
8. Navigation behavior
Desktop nav remains available but visually quiet.
On scroll down, reduce chrome slightly; on scroll up, restore it.
Active route should be visible but not over-emphasized.
Use page transitions only when they make the navigation feel spatially continuous.
