3. Rendering model
Keep content and SEO-relevant text in server-renderable HTML.
Hydrate heavy interactive sections on the client only when necessary.
WebGL scenes should be isolated from normal content components.
Avoid pushing the entire page into client components just because one section is interactive.
4. State model
Global: theme, nav state, reduced-motion, device class.
Section-local: scroll progress, interaction intensity, active item.
WebGL-local: pointer, camera, object transforms, renderer resources.
Do not use a global state library unless complexity genuinely requires it.
5. Motion architecture
Create reusable motion utilities instead of hand-authoring every timeline. Example modules: useScrollReveal(), createTextReveal(), createMagnetic(), createPageTransition(), createScrubbedSection(). Every hook must clean up listeners, timelines and ScrollTriggers on unmount.
6. WebGL architecture
Use a clear scene owner. Example: HeroScene.tsx owns lifecycle; createHeroScene.ts creates the renderer/camera/scene; Hero105Object owns object construction; heroState stores interaction values; disposeHeroScene releases GPU resources. Never scatter renderer creation across random components.
7. Performance budget
Metric
Target
Initial page
Fast contentful render; hero usable before non-critical scenes finish.
WebGL
Aim for stable 60 FPS desktop and acceptable 30–60 FPS mobile on mid-range devices.
Images
Modern compressed formats, correct dimensions, lazy loading below fold.
JS
Keep page-level client JS limited; split heavy interactive modules.
Accessibility
No major automated a11y issues; keyboard navigation complete.
Layout stability
No avoidable jump during font/image/3D initialization.
8. Dependency policy
Before adding a library, check whether a browser API, CSS feature or existing tool already solves it.
Prefer official / maintained packages.
Record why high-impact dependencies exist.
Keep 3D, motion and content code separable so they can evolve independently.
9. Deployment
Keep main stable, use feature branches for experiments, run a local visual verification pass for every feature, use Vercel preview deployments before production, and keep environment variables out of source control.
