2. Voice
Confident but not arrogant.
Technical without sounding like documentation.
Specific instead of buzzword-heavy.
Prefer verbs: design, build, connect, automate, ship, refine.
Avoid empty claims such as “world-class”, “cutting-edge”, “revolutionary” unless proven.
3. Founder story
The Room 105 story should be concise: “Studio 105 started in a room shared by Umer and Saqlain. We began by making things together, then turned that habit into a studio.” The final wording can become more personal later, but the site should keep the origin grounded.
4. GitHub usage rule
GitHub profiles are not a portfolio database. Umer: https://github.com/SMPanther. Saqlain: https://github.com/sqln-ctrl. Cursor must not automatically import repositories into the site. Instead, maintain a manually curated projects.json or content file. Each selected project gets an explicit approval, title, role, summary, visuals, technology list and outcome.

6. Case study content template

7. Blog / Notes
Use Notes for thinking, experiments and technical breakdowns.
Potential categories: AI, creative development, experiments, process, web performance, 3D/web graphics.
Posts should have an opinion or useful lesson; do not publish filler simply to make the blog look active.
